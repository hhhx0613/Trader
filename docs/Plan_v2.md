## 一、系统概述

**LLM 决定"买哪几只"，PPO 决定"总仓位下多重注"，规则决定"准不准下"，程序忠实执行。**

- 定位：以 LLM Agent 应用为核心，PPO 强化学习作为仓位融合器，规则作为安全护栏

- 分工原则：**LLM 只做语义/事件理解，绝不直接处理数值行情数据**；数值择时与仓位全部交给 RL 与量化公式

- 目标：方法科学、评估严谨、结论诚实（包括如实报告负结果）

- 硬件：普通笔记本、纯 CPU 可跑

### 架构

```

          ┌─ 选哪几只 (Top-K, 周频) ─┐   ┌─ 总仓位 (周频) ─┐   ┌─ 否决权 ─┐
新闻/财报 → [LLM Analyst Agent] → 排序打分 → [PPO 仓位融合器] → 仓位档位 → [规则风控] → 最终持仓 → [程序执行]
技术指标  ────────────────────────────────────────────────↑
市场环境  ────────────────────────────────────────────────↑
账户状态  ────────────────────────────────────────────────↑
历史分析 (L1 记忆) ────────────────────────────────────────↑
```

### 决策流程

1. **LLM Analyst**（每周调仓日）：读候选股新闻 + L1 记忆（上次判断与实际结果反馈）→ 输出 per-news 四维打分 → 代码端确定性计算 `composite_score`（方向+强度）与 `confidence`（证据质量）→ 按 `composite_score × confidence` 排序选出 Top-K（K=5，持有优先）

2. **PPO 仓位融合器**（周频/调仓日）：输入 = LLM 观点特征（含信号新鲜度）+ 技术数值 + 市场环境 + 账户状态 → 输出总仓位档位 {0/25/50/75/100%}

3. **规则风控**：只缩减或否决，不凭空加仓（R1 单笔止损、R1a ATR 动态止损、R2 日内回撤禁买）

4. **程序执行**：T-1 生成信号 → T 开盘撮合，忠实执行并记录

### 核心设计决策

| 决策       | 方案                                                               | 理由                                                          |
| -------- | ---------------------------------------------------------------- | ----------------------------------------------------------- |
| 选股       | Top-K（K=5）按 `composite_score × confidence` 排序 + ISO 周锚定调仓 + 持有优先 | 乘积 = 期望信号强度；周锚定保证 LLM 缓存跨回测复用                               |
| 仓位       | 公式版：波动率目标 + 逆波动率加权；**PPO 版：stage1 接管总暴露（已接入真实回测，见 6A）**，个股权重仍逆波动率 | 数字交给 RL，LLM 不碰数值                                            |
| 置信度校准    | ❌ **已否决并禁用**（v1 阶段 4 的 L-Calibrate）                              | 实测一年期收益 10.00% → 3.78%，校准方向错误；样本量不足以支撑可靠校准。**负结果保留作论文消融素材** |
| 技术面      | 不用 LLM，交给量化指标 + PPO                                              | LLM 数值推理弱、不可复现、成本高                                          |
| 牛熊适配     | 单 PPO + regime 特征，不训练多个 PPO                                      | 避免数据切碎和未来函数                                                 |
| 数据缺失     | 返回空 DataFrame 或观点填中性、置信度 0，禁止模拟数据兜底                              | 保证实验真实性                                                     |
| Agent 记忆 | L1 分析上下文记忆（已实现）；L2+ 按需扩展                                         | 消融证明有效（+73% 收益提升）                                           |
| 实验追踪     | 轻量注册表（SQLite）+ 按需对比脚本                                            | 见第五节                                                        |

### 阶段 6 · PPO 仓位融合器：两阶段训练（约 2.5–3 周）🔨 进行中（阶段一/二已训，正接入真实回测）

**核心矛盾**：PPO 日频训练需要几千个以上样本，但 LLM 信号只有约 1 年历史（新闻受 AV 25 次/天配额限制，继续回拉历史不现实）——直接在 1 年数据上训 PPO 必过拟合。

**解决思路（两阶段训练）**：

```

阶段一（预训练）：纯数值特征 × 10 年行情 × 多股票池  →  学会通用的仓位择时
        ↓
阶段二（微调）：  + LLM 特征 × 1 年真实信号窗口      →  学会利用语义信号增强择时
```

仓位决策的绝大部分可学信号（波动、趋势、回撤、成本）都在行情数据里，这部分数据免费且充足；LLM 语义信号是增量信息，只需在**冻结的预训练主干**上挂一个**极小旁路网络**做增量修正（见 6B）。这符合「数字交给 RL，LLM 只做语义」的分工原则。

#### 6A. 阶段一预训练（约 1.5 周）

- 新实现 `core/ppo/`（env / trainer / policy）；decision_func 签名对齐 `MultiStockBacktestEngine` 回调

- PPO 只输出总暴露；个股权重沿用 Top-K 选股结果 + 逆波动率加权

- 恢复训练脚本 `scripts/train_ppo.py`

**阶段一预训练设计**：

- **状态向量（阶段一主干只吃 13 维纯数值，不接 LLM）**：

  - 技术数值 6 维：avg_rsi, avg_macd, avg_adx, rsi_extreme, trend_strength, momentum_avg

  - 市场环境 4 维：market_volatility, market_regime, rolling_20d_ret, sector_corr

  - 账户状态 3 维：current_exposure, drawdown, trade_freq

  - 归一化约定：全部 13 维统一到 [-1,1]。有固定量程的减中心再缩放（avg_rsi=(x−50)/50、avg_adx=(x−25)/25 clip，ADX 中性阈值取 25：<25 无趋势→负、>25 有趋势→正）；厚尾无界量用 tanh(x/典型量级)（macd/收益/波动率）；占比与相关系数天然有界。**avg_adx 旧式 clip(x/50,0,2) 值域 [0,2] 破坏尺度一致性，已改零均值 [-1,1]**

  - LLM 5 维（mean_conf, max_conf, mean_signed_score, max_abs_signed_score, signal_age）：阶段一**不输入主干**，留待阶段二经旁路网络注入（见 6B）。主干永远只看 13 维数值，两阶段输入分布严格一致、杜绝冻结主干 OOD——省掉旧设计"先学会忽略 5 维再唤醒"的别扭环节

- **数据增广**（解决样本量的真正杠杆）：

  - 股票池扩充至 30–50 只（跨行业），每个 episode 随机抽 5 只子池（对齐 `TOP_K`，见本节末「env 底层口径对齐真实回测」）→ 防过拟合特定股票

  - episode 随机化：随机起点、随机长度（6 个月 ~ 2 年）、随机子池 → 组合数爆炸，等效样本量远超 250

  - 行情用 yfinance 拉 2015 年至今，覆盖多个市场 regime

- **数据划分**（防未来函数）：

  - 训练：2015 ~ 2022；验证：2023 ~ 2024；**2025-08 ~ 2026-08 留作最终样本外测试**（与 LLM 信号窗口对齐，阶段二和回测对比都用它）

  - **落地实现（最小可行）**：阶段一/二训练区间不相交，`train_ppo.py` 分别加载两份 `market_data`——阶段一用 `PPO_STAGE1_START/END_DATE`（2015-01-01 ~ 2022-12-31），阶段二沿用 `DEFAULT_START/END_DATE`（2025-08-11 ~ 2026-08-09）。行情一次性拉 2015-01-01 ~ 2026-08-09 存缓存，两阶段按区间切片（`_find_covering_cache` 支持从覆盖大缓存裁子区间）。**验证集 2023-2024 + 早停暂缓**（工程更大，后续按需补），当前阶段一直接训满 `total_timesteps`。

  - **行情缓存约定**（对标新闻「假设 4」，但更简单）：新闻因 AV 单次≤1000 条**必须分段** → 需全局网格锚定去重；行情经 yfinance **一次返回整个区间**、无需分段，故**不套网格**。约定为：每股保留**一个覆盖最广的缓存文件**（如 `{SYM}_2015-01-01_2026-08-09.csv`），所有子区间请求走 `_find_covering_cache` 复用+裁剪（已实现，market_data.py:54 / 92-95）；被完全覆盖的旧窄文件应清理，避免精确区间文件名（`{symbol}_{start}_{end}.csv`）随请求端点漂移而堆积重叠冗余。

- **训练配置**：SB3 PPO，64×64 tanh 网络，纯 CPU，多种子（≥3）

- **奖励**：**差分夏普比率**（Differential Sharpe Ratio, Moody & Saffell 2001）——用 EMA 递推 A_t/B_t，reward = ΔA − η·ΔB，直接优化风险调整收益、与评估指标（夏普）对齐，免去手调 α/β/γ；真实成本（`COMMISSION_PER_TRADE` + 滑点 `SLIPPAGE` + 换手惩罚 `TURNOVER_PENALTY_RATIO`）计入组合回报后再算夏普

- **动作空间**：离散 5 档 {0/25/50/75/100%}，不变

- **真实回测接入（stage1 择时接管总暴露）**：训练/评估在 `env` 的等权子池里进行，但真实回测 `MultiStockBacktestEngine` 走的是「LLM 选股 + 逆波动率权重 + 波动率目标公式暴露」。为让 stage1 的择时能力落到真实组合、与 B&H/LLM/VADER 同口径对比，接入方式如下（**只换总暴露这一个旋钮，选股与个股权重原封不动**）：

  - `core/ppo/predict.py::PPOExposurePredictor`：加载 `models/ppo_stage1`（**不建 env**，`PPO.load` 只用 policy + 存盘 observation_space 做 `predict`），复用 `features.build_numeric_obs` 拼 numeric(13)、`zeros_llm()` 占位 llm(5)，贪心动作 → `EXPOSURE_LEVELS[action]`。

  - **特征一致性（命门）**：引擎的行情在 `run_backtest.download_data` 里被裁回 `start_date`，回测前 ~60 交易日的长窗口特征（regime/相关性/中期收益）会因历史不足而偏离训练分布（env 从 index≥_LOOKBACK 才开始 episode，每个决策点都有完整 60 日窗口）。故预测器**自持一份行情**，用 `data.load_market_data` 从 `start_date` 再回扩 120 日历天加载，保证每个决策日都有完整 60 日窗口、与 stage1 训练/评估口径逐位一致。

  - **接入点在 engine 层而非 decision_func**：numeric 的账户 3 维（current_exposure/drawdown/recent_trades）需要运行时账户状态，`decide_func` 签名拿不到现金/持仓/净值。故 `MultiStockBacktestEngine` 新增可选 `exposure_predictor` 回调，在调仓日 `decide_func` 返回后、仅覆盖 `decision["exposure"]`；账户状态由引擎重建（exposure=持仓市值/净值、drawdown=净值距峰值、recent_trades=近 20 日发生换手的天数，口径对齐 `env._get_obs`）。

  - **run_backtest 新增「PPO Top-K」策略**：复用 `decide_formula_llm` 选股 + 挂 `exposure_predictor`，与「LLM Top-K」（公式暴露）构成「同一选股、暴露公式 vs PPO」的干净 A/B。

- **env 底层口径对齐真实回测（消除迁移鸿沟）**：stage1 接入后实测 PPO Top-K 夏普仅 **0.50 / +8.09%**，远低于 env 样本外评估的 **2.852 / +17.90%**。诊断为训练 env 与真实回测的口径鸿沟——env 底层是「等权随机子池 + 日频调暴露 + 轻成本」，真实回测是「LLM 选 5 只 + 逆波动率加权 + 周频 + 真实成本」；且 env 那 +17.90% 大部分是「等权 10 只龙头」的牛市 beta（B&H 等权满仓同期 +32.05%），非择时 alpha。PPO 在等权平稳组合上学到的日频择时无法迁移到集中持仓的周频组合。故改造 `PPOEnv` 底层口径逐条对齐真实回测：

  - **个股权重：等权 → 逆波动率加权**。σ_i = ATR/close（对齐 `decision_func._stock_daily_vol`），w_i = (1/σ_i)/Σ(1/σ_j)，组合日收益 `day_ret = Σ w_i·ret_i`（取代旧 `subpool.mean()`）。权重每周初按当期 ATR 重算、周内固定（对齐真实回测调仓日重算权重）。

  - **决策频率：日频 → 周频**。每 step = 一个 ISO 周（对齐 `REBALANCE_WEEKLY` 的 ISO 周锚定），PPO 每周决策一次暴露、周内暴露固定，周收益 = 周内每日 `(1 + exposure·day_ret)` 累乘 − 换手成本。episode 长度单位由「天」改「周」。

  - **子池大小：全池 10 → 5**（对齐 `TOP_K`）。每 episode 随机抽 5 只、episode 内固定，模拟真实回测的集中持仓（而非等权 10 只的满 beta 分散）。

  - **市场特征聚合：全池 10 只，与持仓子池分离**（消除 env→真实回测的「感知口径」鸿沟）。numeric 的市场 10 维（avg_rsi / regime / sector_corr…）在**全池**上横截面聚合，持仓组合仍用随机 5 只子池——对齐真实回测：predictor 收 `candidate_pool`（全池）算市场特征、只控制 LLM 选出的 5 只暴露。**感知（全池 regime）与控制（5 只持仓）解耦**的理由：① 全池聚合的 regime 信号横截面方差更小、更稳；② 避免 PPO 把「自己持仓的表现」误当「市场信号」而过拟合特定子池。

  - **成本**：沿用对暴露变化收费，`_COST_RATE = SLIPPAGE + TURNOVER_PENALTY_RATIO`（已是真实值 0.002）。

  - **有意保留的差异**（stage1 职责边界 + KISS）：① env 不模拟 LLM 选股智能（随机抽 5 只而非「选看好的 5 只」）——stage1 是纯数值择时，只学「给定组合调总暴露」，随机 5 只 + 逆波动率已还原集中持仓组合的波动结构，PPO 的择时应对任意 5 只组合通用；② 个股权重变化产生的换手成本暂忽略（二阶效应，主成本是暴露变化）。

  - **连带影响**：差分夏普的 η/scale 可能需按周频收益量级重新标定；`test_ppo_env.py` 适配周频；`ablation.evaluate_policy` 评估口径自动随 env 变周频（`n_days` 语义变 `n_weeks`）。

  - **验证闭环**：重训 stage1（新口径）→ 重评估样本外 → 重跑真实回测 PPO Top-K，检验夏普能否从 0.50 回升、鸿沟是否收窄。

#### 6B. 阶段二微调：Residual LLM Adapter（约 1 周）

**方法**：**冻结主干 + 旁路网络**（residual adapter，类 LoRA），取代原「加载权重 + 低学习率全网络微调」——在 ~250 样本下零灾难性遗忘、仅百级参数可训、且消融友好。

- **主干冻结**：阶段一的 features_extractor + mlp_extractor + action_net + value_net 全部 `requires_grad=False`，仅新增旁路参与梯度更新。

- **actor + critic 双旁路（缺一不可）**：actor `logits = 主干logits + actor_adapter(llm5)`（Linear(5,16)→ReLU→Linear(16,5)）；critic `value = 主干value + critic_adapter(llm5)`（→Linear(16,1)）。**为何 critic 也要**：PPO 是 actor-critic，critic 看不到 LLM 特征会使 advantage `A=Q−V(s)` 系统性有偏、旁路梯度失真——最易踩的坑。

- **zero-init（关键）**：两旁路末层 weight/bias 置 0 → 阶段二起点严格等于阶段一策略，从零学「修正量」，避免随机旁路瞬间摧毁预训练成果。

- **观测分离**：env obs = `Dict{numeric: Box(13), llm: Box(5)}`；主干经 `NumericExtractor` 只取 numeric(13)，与阶段一输入分布严格一致（阶段一主干本就不接 LLM，杜绝冻结主干 OOD）。

- **权重迁移 + 优化器**：主干 key 与阶段一一致，`load_state_dict(strict=False)` 迁移主干、保留旁路 zero-init；重建 `Adam(仅 adapter 参数, lr=1e-4)` 避开 weight decay 衰减冻结参数的陷阱；少量 timesteps，按验证窗口夏普早停。

- **窗口 + walk-forward**：2025-08 ~ 2026-08（真实 LLM 信号，周频生成、日前向填充 + `signal_age`，沿用 `_compute_llm_features` 语义）；2025-08 ~ 2026-03 微调、2026-04 ~ 2026-08 最终样本外（只碰一次）。

- **消融红利**：旁路输出天然量化 LLM 边际贡献——对比「有旁路 vs 旁路置零」的期望仓位档位偏移、改变决策天数占比、value 边际贡献，直接回答下表「LLM 信号有无增量价值」。

- **兜底（逐级降级）**：① advantage 不稳 → 解冻主干 value_net 末层同训；② 加性融合学不到「条件交互」（如仅高波动时 LLM 才该放大仓位）→ 若消融增量不足，把 market_volatility/regime 等 2–3 维数值拼进旁路输入使其条件化（不上 FiLM/gating，避免过度设计）；③ 在线 PPO 训不稳 → 改离线 RL（d3rlpy CQL/IQL，代价是新增依赖）；④ 仍无正收益 → 降级为消融项诚实报告负结果（参照置信度校准先例）。

### 假设 2：多因子选股打分
